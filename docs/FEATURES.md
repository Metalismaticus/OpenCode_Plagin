# Карта сохранённых функций

Источник поведения: CLAUDE_Game **0.10.6**, коммит
`ab79866b43b4bf1fb388826a77265f3a385a46ad`.
`build/source-lock.json` фиксирует источник и контрольные суммы всех 23
протоколов: 17 команд и 6 исходных ролей. Главы сохраняются целиком;
новые короткие роли и skills маршрутизируют к применимой главе.

| Исходная функция | Где сохранено | Что добавлено или изменено |
|---|---|---|
| Два чата, замысел человеческими словами | AGENTS, idea, ASKING | Фиксируемый режим сессии; product/architect помогают внутри системы |
| `/setup`, образцы до вопросов, живое первое окно | protocols/commands/setup, setup-steps, templates | Каркас через bootstrap-карточку executor; замысел останавливается до запуска продукта |
| ROADMAP, этапы, покрытие и вертикальные срезы | roadmap, idea, roadmap_check | Роли не получают весь процесс целиком |
| Фиксированная партия, cleanup limits и scope | start/02–03, BATCH | Карточка со словами владельца и конкретными файлами; грязные исходные файлы не присваиваются |
| Исполнитель → независимый проверяющий | executor, reviewer | Ролевые переходы; отдельные выводы о требованиях и качестве |
| Не больше трёх кругов | start, reviewer | Счётчик в коде; новая карточка того же шага не обнуляет круги |
| Красное доказательство или честная неприменимость | executor/02 | Обязательный red_proof; реальные проверки backend вместо переданного exit code |
| Сценарии через ввод | executor, reviewer, TESTING | Godot skill напоминает границу headless/визуального доказательства |
| `[ui]`, спецификация designer | designer, DESIGN, docs/specs | Спецификация сохраняется предварительным документальным коммитом; код имеет собственный checkpoint |
| `[вид]`, `[ощущение]`, варианты приёмами | start/06, executor/03–04, reviewer/03–04 | Карточка на каждый шаг; промежуточные стадии — checkpoints, финал — приёмка |
| «Вижу», «было / стало / образец», отсутствие vision | done, look_sheet, LOOK_TECHNIQUES | Невозможность видеть не превращается в заявление о сходстве |
| «Как увидеть», «Решено за вас», ловушки | исходные форматы ролей и BATCH | Поля structured report; смысл и русские ярлыки сохранены |
| Worktrees, волны и тяжёлые проверки | scout, start/05, TESTING | Общее состояние main/слотов; relocate проверяет содержимое после merge |
| Performance budgets, probes, quality ladder | start/09, TESTING, perf_ref | Отдельный Godot/shader skill; реальные checks сериализуются |
| Код не разрастается: baseline/ratchet | code_check, TESTING, executor/reviewer | Baseline не правят workers; исходные тесты скрипта сохранены |
| Отказы владельца, частичная приёмка, revert | done/02–06 | Решение и причина берутся из наблюдаемого user/question ответа; запись отказа сама не объявляет откат выполненным |
| Обрывы, парковка, общий пробел, budget | start/07 | Машинное состояние; adopt/recover не придумывают прошедшее ревью |
| Ассеты, заказы, права, проверка GLB | order/add/need, assets, model/asset_check | Исходные главы и шаблоны сохранены |
| `/check`, `/parallel`, `/retro`, `/release`, README | соответствующие исходные протоколы, COMMITS | Короткие входы; существующие ограничения публикации сохранены |
| Git guard и контекст сессии | исходные Python-хуки + адаптер V2 | Поломка guard блокирует shell; после compaction добавляется актуальная краткая стадия |
| Переключаемые модели и токены | models/configure + telemetry | Фактическая модель сверяется с профилем; fallback явно отдельный |
| Установка в реальный проект | install.py / install.ps1 | Убрано `/MIR`; чужие плагины и настройки сохраняются |

## Приоритеты правил

1. Слова владельца и согласованные проектные документы определяют результат.
2. Runtime определяет стадию, круг, исполнителя, scope и доказательства проверок.
3. Skills указывают, когда читать исходную главу, и адаптируют API OpenCode.
4. Исходная глава определяет подробный способ работы внутри этой стадии.

Старый однострочный вызов Agent из оригинала заменён id карточки и источниками;
старые названия `AskUserQuestion`, `CLAUDE.md`, пути плагина — платформенным
адаптером. Загрузка skills workers теперь разрешена. Полное знание студии
больше не обязано постоянно находиться в роли исполнителя.

Основные пользовательские функции не урезались. Сверка сохранённых текстов
не является доказательством, что модель выполнила их в живом проекте.
