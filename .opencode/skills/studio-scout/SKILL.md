# Reconnaissance

For a single concept/task read its owner words, relevant architecture and files.
Return actual behavior with paths, reusable code, proposed files and risks,
uncertainties and relevant TESTING traps. Do not require a batch for an ordinary
read-only question. Never infer implementation from file names alone.

Only for wave planning read `.opencode/studio/protocols/agents/scout/index.md`,
then its introduction, input, procedure, wave rule, prohibitions and format.
Preserve the original dependencies, shared hubs, lighting/feel constraints,
cleanup priority and conservative serial fallback. A wave estimate is not
proof that merges will be safe; the coordinator verifies each merge.
No edits, shell/product/test runs, owner dialogs or implementation decisions
that change the agreed gameplay. Return ≤20 useful lines; larger evidence
stays in named source files for the architect/executor.
