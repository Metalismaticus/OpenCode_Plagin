## Итог координатору

Не больше 20 строк (строки `уборка:` — сверх, не больше 5; «Вижу:» — сверх,
по строке на снимок), без логов, вывода проверок и содержимого файлов.
Строки — ровно эти («Кадр», «Вижу:» и «Против образца» — у `[вид]` и `[ui]`
со снимками, «Способ» — на основе и выборе `[вид]`, «Лист» — на основе и
выборе `[вид]` и `[ощущение]`, «Пресет» — у пунктов с рендером):

```
Пункт N: готово | не удалось | ждёт
Файлы: <пути, которые пункт создал или изменил>
Красное без исправления: <команда> → <строка провала> | неприменимо: <почему>
Зелёное: <команда> → <итоговая строка>
Проверки: <проверка пункта> и группа <имя> — <зелёных>/<провалов> | <первая ошибка>; здоровье: чисто | исправлено N | заметок M | мерить нечем; типы: чисто | <первая ошибка> | нет
Как увидеть: <1–3 шага в продукте: где (экран / место, seed, координаты) → что должно быть видно или слышно>
Кадр: look_sheet.py --sanity — чисто | нет режима
Вижу: <снимок> — <что в кадре словами продукта: предмет, форма, края, что не так>
Против образца: <чем похоже / чем явно не похоже>
Способ: <составляющая — приём <имя из паспорта> — где в коде; отступ — с причиной; «меняю способ: приём <было> → приём <стало>, потому что <что видно>»>
Лист: <A — приём <имя> | файл <путь>: чем отличается (у `[ощущение]` — числа), цена в кадре (мс, оценка); B — …; час <час паспорта>; пути листов, JSON, `variant-`>
Пресет: <на каком пресете графики снято и проверено; у лестницы качества — «высокие» и «низкие»> | единственный: настроек графики нет | <какой> — стенд не умеет
Решено за вас: <[видно] | [техника] что — почему — чем обойдётся, если неверно; по строке на решение> | нет
Ловушка: <неочевидная ловушка стека или проекта, найденная по ходу> | нет
Коммит: <Item N: | Пункт N:> <что изменилось для игрока>
В документы при /studio/done: <1–4 строки>
Замечено вне пункта: <одной строкой; каждая уборка — своей строкой `уборка: …`> | нет
Вопрос владельцу: <блок ниже, только при «ждёт»>
```

**«Решено за вас» — с меткой:** `[видно]` — владелец это видит, слышит или
чувствует в продукте (цвет, размер, раскладка, скорость); пишется словами
продукта: что видно сейчас и что изменится, если поменять, — без чисел
вместо смысла («контур чуть темнее самой тёмной стороны модели», а не
«обводка 0.55»). `[техника]` — внутреннее (как мерить, где хранить, формат
файла); его `/studio/done` владельцу не показывает.

**«Как увидеть» — шаги в продукте, а не в коде:** по ним смотрит владелец и
снимает проверяющий; у бага — место из «Где», пункт без видимого следа — где
ничего не должно измениться. Листы, JSON и `variant-` — только в «Лист», не в
«Файлы»: их коммитит координатор вместе с выбором (`Партия: пункт N — выбор K`).
«В документы при /studio/done» — для «Сделано» (словами игрока), CONCEPT, TESTING,
BUGS, BLOCKED, DESIGN. «Замечено вне пункта» — не чинить; структурное
(разрослось, повторено, мёртвое) — с префиксом `уборка:`, как строка
`code_check`: `уборка: <файл> — <что> — <как исправить>`, по строке на
уборку (можно несколько строк).

**«Коммит» — первая строка сообщения**, тело соберёт координатор из «Как
увидеть» и «Проверки». Пометка — по «Язык коммитов» в «Git» `AGENTS.md` (нет
строки — язык из шапки `docs/BATCH.md`); до 72 знаков; что изменилось для
игрока, без метафор, пустых слов и имён из кода: «Item 3: Let players dig
through stone with a pickaxe» / «Пункт 3: копать камень киркой»
(`reference/COMMITS.md` плагина). На шаге «стенд вида/ощущения» — `Item N:
Add the look|feel stand` / `Пункт N: стенд вида|ощущения`; «основа» — `Item
N: Base — <что изменилось>` / `Пункт N: основа — <что изменилось>`;
`Уборка:` — `Item N: <что> (no change for players)` / `Пункт N: <что> — для
игрока без изменений`.

Блок «Вопрос владельцу» — 2–4 варианта; технический вопрос не задаётся
(п. 7); координатор задаст его владельцу без пересказа:

```
Вопрос владельцу: <вопрос одной строкой, самодостаточный, словами продукта>
- <вариант> (Recommended) — <что будет, если выбрать>
- <вариант> — <что будет>
Пока нет ответа: <что агент сделал или что делать дальше без ответа>
```
