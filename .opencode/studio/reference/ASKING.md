# Как спрашивать владельца

Общие правила для всех команд studio, где есть вопросы. Скилл ссылается на
этот файл одной строкой и правила не копирует. Владелец — не программист. Среда — OpenCode: **окно вопроса — встроенный
инструмент `question`**: короткий `header`, вопрос и варианты (label +
description «что будет, если выбрать»), `multiple` — выбор нескольких,
свободный ответ («напишите словами») доступен всегда. Все правила ниже
про «окно» понимаются так.

## Правила

1. Любой вопрос с выбором — окном: инструмент `question`. До окна — только
   короткое пояснение (≤ 5 строк) и итог после. Длинное — в файл, в чат —
   путь к нему.
2. Спрашивать только о решениях владельца: замысел, вкус, приоритет, приёмка,
   деньги, необратимое; порядок этапов и состав первой версии — тоже его.
   Необратимое — сохранения и данные игрока, выпущенное, деньги; удалить
   код, копию или файл, которые остаются в git и откатываются, — не оно.
   Факты искать самим; технику решать самим и называть строкой «Решено за
   вас». Технические пункты очереди — проверки, баги, замеры, уборка кода
   (`Уборка:` — перенос, одна копия вместо двух, файл по частям, тип записи
   одной сущности), в том числе из заметок разработки, — владельцу окном не
   предлагать: чат ставит их сам
   и называет одной строкой в «Принято по умолчанию». Переписать систему
   целиком — не уборка, а решение владельца через `/studio/roadmap`. Порядок
   и способ работы — что сначала, как показать, какой кадр снять, как обойти
   помеху — тоже не вопрос: в `/studio/start` координатор берёт рекомендуемое и
   пишет в «Принято по умолчанию» `docs/BATCH.md` и в отчёт строку `Решил
   сам: пункт N — <что> — <почему>; отменить — при /studio/done` (для всей партии —
   `партия` вместо номера; агент — в «Решено за вас»). Железо игроков после
   пробы рендера — тоже: следствие нового рендера для правил проекта
   (минимум по замеру) называется строкой «Решил сам», окном не спрашивается.
   **Какой вариант ближе к образцу — не вопрос**: сравнить с образцом —
   работа агентов, вариант `[вид]` и `[ощущение]` выбирает координатор
   (`/studio/start`, 3б), владелец судит результат в `/studio/done` — принять или
   отклонить своими словами.
3. Окно: 1–4 вопроса, 2–4 варианта. «Другое» не добавлять — оно есть само,
   вместе с полем заметки. Можно выбрать несколько — `multiple` у вопроса. Больше
   четырёх вариантов — делить на вопросы поровну (5 = 3 + 2); остался один —
   обычный вопрос «<суть>: …?» с двумя вариантами. В `multiSelect`, где
   «ничего» — законный ответ («что оспорить», «какие пункты принимаете»),
   **«ничего» — явный вариант**, а не пустой выбор:
   пустое `Submit` владельцу неочевидно. Если «ничего» — ожидаемый ответ
   («Всё так, ничего не менять»), он первый и `(Recommended)`; иначе —
   последний («Ничего из этого»). Тогда других вариантов в вопросе — до
   трёх. Выбран вместе с другими — считаются другие.
   Абстрактного «что вам не нравится?» без конкретного выбора окном не
   задавать: вопрос — только с вариантами, понятными без пояснений; иначе —
   строки текстом и «Не так — напишите …» (`/studio/done`, «Решено без вас»).
   Владелец сам назвал ответ («только 1», «кроме 3») — о нём окна нет.
4. Вопрос самодостаточен (`header` — не пересказ вопроса): номер пункта и
   суть в тексте вопроса. Тексты вопросов в одном окне разные — ответы
   привязаны к тексту. `header` нужен: ≤ 12 символов.
5. label — 1–5 слов; description — одна строка «что будет, если выбрать».
6. Рекомендуемый вариант — первым, label кончается `(Recommended)`, причина — в
   description. Вкус, которого не вывести ни из слов, ни из образца (`/studio/idea`),
   — без `(Recommended)`.
7. «Пока не знаю» — законный ответ: вопрос уходит в «Решения» `BLOCKED.md`,
   необратимое по умолчанию не делается.
8. Не больше двух окон подряд, если следующее не вытекает из ответа на
   прошлое; дальше — итог «записал так-то». Цепочка, где вопрос вытекает из
   ответа (`/studio/done`: выбор → причины → проход по пунктам), не ограничена.
   `/studio/roadmap` — не больше двух окон вопросов и окно «Принять» (с вопросом о
   чужом файле плана); противоречие в ядре замысла или «Какой замысел
   главный?» — ещё одно окно; «Поправить …» и «Ещё поговорить» после
   «Принять» вытекают из ответа; остальное — допущениями.
9. После ответа — строка «Понял: …» и запись **дословно** в нужный документ
   (заметки владельца — тоже дословно).
10. Картинки — никогда в окне: сначала путь к файлу (владелец открывает
     его сам, во весь размер); потом окно. Кадры `[вид]` и
    пробы в `/studio/done` — на весь экран в просмотрщике, игра или стенд
    `[ощущение]` — открыты самим чатом до окна «что принимаете?» (`/studio/done`,
    раздел 2).
11. Субагенты не спрашивают: инструмента у них нет. Нужен ответ — блок
    «Вопрос владельцу» в конце итога; координатор превращает его в окно без
    пересказа (в `/studio/start` — сначала по п. 2 и 12):

    ```
    Вопрос владельцу: <вопрос одной строкой, самодостаточный, словами продукта>
    - <вариант> (Recommended) — <что будет, если выбрать>
    - <вариант> — <что будет>
    Пока нет ответа: <что агент сделал или что делать дальше без ответа>
    ```

    `Вопрос владельцу (можно несколько): …` — вопрос с `multiple`; выбрать
    можно несколько вариантов сразу; `(Recommended)` в таком блоке не
    обязателен.
12. **`/studio/start all` работает без присмотра:** владелец дал команду и ушёл.
    После снятия партии окон до конца запуска нет, и работа не ждёт ответа:
    - вопрос «что делать» (замысел, вкус не по картинке, приоритет, деньги,
      необратимое), всплывший в партии, — пункт `ждёт: <вопрос>`, вопрос —
      строкой в «Решения» `docs/BLOCKED.md` для сценариста — чата замысла
      (`— /studio/need`; нужен разбор или новый образец — `— /studio/idea …`), партия идёт
      другими пунктами; в отчёте — «Вопросы в сценарист: N — /studio/need», не
      окно. Одиночный `/studio/start` спрашивает сразу;
    - окна — только в конце запуска, не больше двух, и только то, что нельзя
      ни решить без владельца, ни отложить (редко). Выбора варианта и пары
      кадров пробы среди них нет — ни в конце, ни по ходу: вариант выбирает
      координатор (п. 2; ось «покажем оба» — по словам владельца), вид
      владелец судит в `/studio/done`. Замеры — без окна: координатор мерит сам.
      Вопросы копятся в «Вопросы владельцу» `docs/BATCH.md`; неотвеченное
      остаётся там, в `BLOCKED.md` его переносит `/studio/done`.

    Чтобы партии было что делать, вопросы «что делать» задаёт сценарист до
    запуска: `/studio/idea` ставит `[можно]` только пункту без открытых вопросов
    (оговорка `[предварительно]` — тоже вопрос); предпочтение, которого не
    вывести ни из слов, ни из образца, ни из «Правил стиля», — там же, до
    очереди (редко).
13. **Вид — словами продукта, без техники.** Пара кадров пробы (смена
    рендера, дорогая возможность) — не окно: `/studio/done` открывает её на весь
    экран со строкой «на вашем ПК тянет / не тянет (по замеру); на слабых —
    неизвестно», таблица чисел — в отчёт. Кадр-цель (`/studio/need`, один раз на
    кадр, в чате замысла): «Кадр-цель <тема>: это место должно выглядеть
    так?» — `Да` / `Нет: …` (заметка — что не так) / `Без кадра-цели`; до
    окна — пути кадра-цели и нашего снимка; кадр-цель — направление по свету,
    палитре, материалу и настроению, не по геометрии: расхождения геометрии
    — не повод для «Нет». Технических вопросов нет.

## Запасной путь

- Окно не поддержано клиентом или отменено — тот же вопрос нумерованным
  списком в чат плюс «или напишите словами».
- Пустой ответ или отмена — повторить один раз; снова пусто — как «пока не
  знаю»; снова пусто — как «пока не
  знаю». Кроме `multiSelect`, где скилл назвал пустой выбор ответом
  («ничего»): это ответ, не повторять.
- «Другое» без текста — спросить словами и остановиться.
- Свободный ответ вместо выбора — главнее вариантов.

## Образец

```
Пункт 3, ночь в игре: опасна?                   ← вопрос, header «Ночь»
- Да, выходят монстры (Recommended) — как в вашем замысле «выживание»
- Нет, только темнее — спокойная прогулка
```

Отчёты и вопросы — словами продукта: не «rebase», «ff-only», имена констант и
файлов кода, а что видно и что изменится в игре или приложении.
