# studio · GLM + OpenCode

Порт плагина **studio** ([CLAUDE_Game](https://github.com/Metalismaticus/CLAUDE_Game),
сборка Claude Code) под OpenCode V2 с моделями GLM.
Процесс не меняется — меняется среда: команды, агенты, роутинг моделей и
обёртка хуков. Исходник (Claude Code) не тронут: репозиторий выше остаётся
работоспособной Claude-сборкой, а этот — OpenCode-сборка.

```
studio-glm/
├── build/
│   ├── models.json     # ЕДИНСТВЕННОЕ место роутинга: роль → модель
│   ├── convert.py      # генерация .opencode/ из исходника (перепроверяемо)
│   └── configure.py    # перешить model: у агентов по models.json
└── .opencode/          # то, что кладётся в проект игры
    ├── agents/         # studio (координатор, модель — пикер чата/глобальный
    │                   # дефолт) + цепочка executor-prep/code/finish,
    │                   # reviewer, reviewer-fast, designer, scout, assets,
    │                   # reference — модель из models.json
    ├── commands/studio/  # /studio/setup, /studio/idea, /studio/roadmap,
    │                     # /studio/start, /studio/done, /studio/board … (18)
    │                     # — базовый слой; видовые ветки вынесены в skills
    ├── skills/           # подгружаемые разделы (инструмент skill):
    │                     # studio-vid, studio-wave, studio-perf,
    │                     # studio-obrazec, studio-concept
    ├── plugins/studio.ts  # обёртка хуков (см. «Хуки»)
    └── studio/           # данные плагина: reference/ (ASKING, COMMITS,
                          # LOOK_TECHNIQUES), setup-steps/, templates/
                          # (AGENTS.md, docs/, tools/), hooks/, env_check.ps1
```

## Установка в проект

1. `git clone <этот репозиторий>` (или скачать ZIP) и скопировать
   содержимое `.opencode/` из этой папки в `.opencode/` проекта игры
   (та же раскладка). Плагин проектный: пути в протоколах считаются от
   корня проекта.
2. Python в PATH (`python -X utf8` — так зовут хуки; проверка:
   `python -X utf8 .opencode/studio/hooks/selftest.py --quick` — должно
   закончиться «61/61 … ок»).
3. В чате разработки: `/studio/setup` → он развернёт `AGENTS.md`, `docs/`,
   очередь и запустит первое окно игры. Дальше — как в оригинале:
   **два чата в одной папке** («замысел» и «разработка», раздел «Два чата»
   `AGENTS.md`).
4. OpenCode перечитывает команды/агентов сам; после правки `studio.ts` —
   `opencode service restart`.

## Роутинг моделей

Весь роутинг — `build/models.json`; смена модели или провайдера = правка
файла + `python -X utf8 build/configure.py`. Сейчас (по доступным в
окружении моделям, флагман — GLM):

| Роль | Модель | Почему |
|---|---|---|
| `studio` (координатор обоих чатов) | **выбор в пикере чата** (без выбора — глобальный дефолт `opencode-go/glm-5.3`) | рычаг владельца: можно перевести координатора на другую модель — например, зрячую (Claude/Gemini) для разбора картинок |
| `executor-code`, `reviewer`, `designer`, `reference` | `opencode-go/glm-5.3` | суждение: красное доказательство + реализация, полная проверка, дизайн, разбор образцов |
| `executor-prep`, `executor-finish`, `reviewer-fast`, `scout`, `assets` | `opencode-go/glm-5.3-flash` | механика: разведка в бриф, доведение (проверки/снимки/лист), лёгкая проверка, волны, пришедшие файлы |

Субагенты моделей из `build/models.json` не меняют никогда (кроме правки файла);
координатор переключается пикером в любой момент — команды `/studio/*` его
не перебивают (у агента `studio` нет своей модели).

**Цепочка executor** (стадия 3): `executor-prep` (бриф-файл: документы,
похожее, ловушки, план красной проверки; снимки «до») → `executor-code`
(красное доказательство + реализация — вместе, инвариант честности
зелёного; **круги 2–3 — только он**) → `executor-finish` (короткие
проверки, находки здоровья, снимки, лист, `look_sheet --sanity`, полный
итог в 20 строк из итогов обоих). Бриф и итоги звеньев — файлы
`../<папка проекта>.wt/rounds/p<N>-r<R>-{бриф,код,итог}.md`: истории чата
нет, всё нужное в файлах — как всегда в studio.

Оплата по токенам: 5.3 — $1.40/$4.40 (кэш-чит $0.26), Flash — $0.15/$0.50
(кэш-чит $0.03). При появлении GLM-5.2 / 4.6V / GLM-Image — добавить роли
в models.json и перешить.

## Чем отличается от Claude-сборки (задокументированные отклонения)

Смыслы и дисциплина — без изменений; среды разные:

1. **Команды:** `/studio:xxx` → `/studio/xxx`; все упоминания в
   документах переименованы. Скиллы стали командами OpenCode (слэш — только
   у пользователя).
2. **`CLAUDE.md` → `AGENTS.md`** — и в проекте, и в шаблонах; старый
   Claude-проект (с `CLAUDE.md`) узнаётся хуком контекста по метке шаблона.
3. **Хуки:** `hooks.json` (PreToolUse/SessionStart) → плагин
   `.opencode/plugins/studio.ts`. Python-скрипты **не переписаны**:
   обёртка подаёт им события в исходном формате Claude; блокировка —
   `throw` из хука `execute.before` (bash/shell). Контекст сессии —
   на первый промпт сессии (`prompt`-хук, дедуп по сессии).
4. **Окна вопросов:** AskUserQuestion → **встроенный инструмент `question`**
   (header ≤ 12 символов, варианты label+description, `multiple`,
   свободный ответ всегда доступен) — ASKING.md перепривязан к нему.
   Субагентам `question` запрещён (по ASKING: не спрашивают — блок «Вопрос
   владельцу» в итоге, координатор показывает окном). Клиент без форм или
   отмена окна — запасной путь: тот же вопрос списком в чат.
5. **Вставка картинок:** `$TEMP/claude/…` нет; вставленная картинка —
   вложение сообщения: агент `reference` сохраняет её байты в
   `docs/refs/<тема>/owner-<дата>-<n>.png`.
6. **Субагенты:** инструмент Agent → `subagent` по имени (`executor`,
   `reviewer`…); повтор упавшего — тем же сообщением; «SendMessage» →
   продолжение дочерней сессии по sessionID. Права (deny `subagent` и
   прочее) переведены из `disallowedTools`/`tools` в permissions V2,
   `maxTurns` → `steps`.
7. **Агент `studio` (новый):** тонкий primary-координатор — «делай» в чате
   разработки значит «прочитай протокол `/studio/start` и выполняй»;
   subagent-права — только студийные агенты. Кэш-дружелюбно: стабильный
   базовый слой промпта, переменное — в конце.
8. **Vision:** в окружении нет 4.6V. Если 5.3 не примет картинки, работает
   деградация протокола: «вид не проверен», выбор по числам листа;
   `look_sheet.py --sanity` всё равно сторожит кадры. При появлении vision-
   модели — в models.json.
9. **Телеметрия токенов** (`/retro`, `/board` — расход по ролям): не
   подделана «на словах» — оставлена на стадию 3 (см. ниже), чтобы цифры
   были настоящими, а не обещанными.
10. **Язык: двухслойный.** Протоколы (тела агентов, команд, скиллов,
   setup-шагов, ASKING/COMMITS/LOOK_TECHNIQUES) — **английский**: их
   читает модель, кириллица стоила бы ~40–50% токенов. Всё, что видит
   владелец — **русский без исключений**: ярлыки итогов (`Файлы:`,
   `Как увидеть:`, `Решено за вас:`), тексты окон `question`, метки
   очереди (`[вид]`, `Уборка:`, `в работе`, `готов к проверке` — их
   парсят python-скрипты), поля паспортов, пары коммитов (`Item N:` /
   `Пункт N:`), документы. Глоссарий перевода — `build/translate-guide.md`,
   проверка остатков — `build/check_translation.py`. Frontmatter агентов
   и команд (description) — русский: его видит владелец в пикерах.

## Телеметрия токенов

Приборная панель экономики (стадия 5, проверена на живом сервере):

- **Пишет** — плагин `studio.ts`: на `session.usage.updated` (обновление
  расхода сессии — идёт на каждый шаг любой сессии; события `session.idle`
  в сервере V2.0.22 нет — проверено живым дампом) и на первом промпте
  сессии — дельта-запись в `../<проект>.wt/usage/studio-usage.jsonl`.
  Строка на каждый ответ модели студии: время, сессия и её родитель,
  агент, модель, токены вход/выход/кэш-чит/кэш-запись, цена в $. Поток
  событий общий на сервер (чужие сессии — мимо, фильтр по `projectID`,
  проверен живым прогоном). Данные — от сервера, не от честного слова
  модели.
- **Читает** — `/studio/board`: строка «токены: <вход>/<выход> (кэш-чит N)
  · ~$X — по ролям» в блоке «Партия»; `/studio/retro`: сводка по ролям
  с момента «Снята …» партии, рядом круги до одобрения из `BATCH.md` —
  таблица «агент → модель → токены → $ → кругов».
- **Надёжность** — дедуп по id сообщений (plugin storage), фильтр по
  проекту, чужие сессии — мимо; любая ошибка телеметрии молчит: счётчик
  не имеет права ломать партию.

## Привязка роли чата

Установка кладёт в проект `.opencode/opencode.json` с
`default_agent: "studio"` — **каждый новый чат в проекте студии рождается
координатором**: код не пишет, «делай/поехали» понимает как протокол
`/studio/start`, вопросы задаёт окном `question`. До этой привязки роль
была факультативной: чат без `/studio/*`-команды оставался обычным
кодинг-агентом OpenCode и мог писать код сам (проверено: свежая сессия
без явного агента отвечает как `studio`). Свободный агент — переключитесь
в пикере на `build`; свой `opencode.json` проекта инсталлятор не
затирает (`/XF opencode.json`).

## Проверка сборки

`python -X utf8 .opencode/studio/hooks/selftest.py` (полный, ~40 с) или
`--quick`. Полный прогон исходной сборки — **все зелёные**: хуки 61/61
(guard_git блокирует те же команды, что в Claude), карта 11/11, код 65/65,
кадры 15/15, образцы 14/14, модели 14/14. `convert.py` падает, если
какой-либо патч не нашёл место — тихих пропусков нет.

**Дымовой тест на живом сервере** (V2.0.22, песочница `pilot/` в этой папке)
— пройден:

- **команда + роутинг:** `/studio/board` через API — выполнился агентом
  `studio` на `opencode-go/glm-5.3`, вывод по протоколу (агент даже сам
  прогнал selftest и сообщил «запреты работают»);
- **страж:** наивный `build`-агент без истории вызвал `shell` c
  `git add -A` — обёртка → `python guard_git.py` → **блок**: модель
  получила дословное сообщение студии («называть файлы поимённо…»);
  заметка: инструмент в сервере называется `shell` (не `bash`) — обёртка
  ловит оба имени;
- **телеметрия:** `pilot.wt/usage/studio-usage.jsonl` пишется строкой на
  каждый ответ (`agent`, `model`, `in/out`, `cacheRead`, `cost`); кэш
  реально работает — на прогоне `/studio/board` 53K токенов пришлись на
  кэш-чит ($0.26/M) против 4K полного входа;
- **дисциплина текстом:** агент `studio` отказался запускать `git add -A`
  ещё до хука — по правилам протокола.

## Дорожная карта порта

- [x] **Стадия 1–2:** каркас + структурная конвертация + хуки + selftest
      зелёный; роутинг моделей в одном файле.
- [x] **Стадия 3 (эта сборка):** дробление executor на `executor-prep`
      (Flash, read-only, бриф-файл) → `executor-code` (5.3: красное
      доказательство + реализация вместе — инвариант честности зелёного)
      → `executor-finish` (Flash: проверки, находки здоровья, снимки,
      лист, полный итог); круги 2–3 — замечания reviewer сразу в
      `executor-code`, prep/finish не перезапускаются; `reviewer-fast`
      (Flash) для лёгкого режима `/studio/start all`; диспетчеризация
      цепочки — в `commands/studio/start.md` (§Главное, §3, §3а);
      права агента `studio` — на новых агентов. `build/convert.py`
      теперь бутстреп: повторный запуск остановлен защитой (— стёр бы
      стадию 3 монолитом).
- [x] **Стадия 4 (эта сборка):** резка толстых промптов — базовый слой
      команды всегда в контексте, видовые ветки вынесены в подгружаемые
      скиллы (инструмент skill, грузятся один раз по метке партии):

      | Файл | Было | Стало (базовый слой) | Вынесено в скилл |
      |---|---|---|---|

      разделов (3а, 3б, 6, 3, 8) сохранена в скиллах — перекрёстные ссылки
      команд не менялись. Субагентам скиллы запрещены (deny skill):
      протокол агента — в файле агента, кэш-стабильный префикс.
- [x] **Стадия 5 (эта сборка):** телеметрия токенов — `studio.ts` слушает
