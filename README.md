# studio для OpenCode

Помогает одному владельцу делать игру: вы говорите обычными словами, что
хочется видеть и чувствовать, ИИ помогает додумать и реализует. Технические
классы, ноды, шейдеры и структуру файлов выбирает система.

Эта сборка переработана **от оригинального CLAUDE_Game 0.10.6**, а не от
архитектуры предыдущего OpenCode-порта. Оригинал остаётся отдельно:
[Metalismaticus/CLAUDE_Game](https://github.com/Metalismaticus/CLAUDE_Game).
Исходная версия закреплена в `build/source-lock.json`.

## Что изменилось

- **Роль** отвечает на вопрос «кто ты»: короткие профили executor, reviewer,
  designer, scout, assets, reference, product и architect.
- **Workflow** говорит, на какой стадии работа: карточка → реализация →
  независимое ревью → контрольный коммит → реальные проверки → приёмка.
  Стадии, роли и три круга исправлений проверяет код `studio_workflow`.
- **Skill** загружает нужный способ работы. Godot, шейдеры, визуальная
  проверка, волны и исходные главы процесса не лежат в каждой роли целиком.

Один плагин, **два отдельных чата в одной папке**. Чат замысла обсуждает
механики и пишет документы. Чат разработки выполняет очередь. Режим
фиксируется на стороне плагина; случайная фраза «сделай» в замысле не
должна превратить его в программиста.

Сохранены исходные команды, ROADMAP/BATCH, «Как увидеть», «Решено за вас»,
визуальные варианты и сравнения, производительность, заказы ассетов,
worktrees, причины отказа и откат непринятого. Точная карта переноса —
[docs/FEATURES.md](docs/FEATURES.md). Правила не выброшены ради коротких
промптов: они вынесены в главы и читаются по стадии.

## Установка

Нужны **OpenCode V2** и Python 3.9+. Конфигурация V1 отличается: эту сборку
нельзя просто положить в V1 и считать совместимой.

В Windows из папки этого репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 "C:\path\to\game"
```

Или на любой системе с Python:

```sh
python -X utf8 install.py /path/to/game
```

Установщик копирует только файлы studio, сохраняет сторонние плагины и
существующий `opencode.json(c)`, сохраняет прежние заменяемые файлы и
проверяет установленные хуки. Не применяет зеркальное удаление `.opencode/`.
Если у проекта свои настройки, выберите **studio** в пикере агента либо
добавьте `default_agent: "studio"` в существующий конфиг самостоятельно.
Не заменяйте весь конфиг: в нём могут быть ваши провайдеры и другие плагины.

Откройте новый чат проекта: `/studio/setup`. Для уже развёрнутого проекта
— `/studio/setup обновить`. Замысел и документы прежнего проекта сохраняются;
старую активную партию сначала сверяют с git. Ей нельзя приписать прошедшее
машинное ревью задним числом: нужна новая карточка и реальная проверка.

Обновление плагина должно перечитать его код; перезапустите сервис OpenCode,
если он продолжает использовать прежний модуль. Встроенные формы вопросов
зависят от клиента; исходный запасной путь текстом сохранён.

## Как пользоваться

В чате замысла:

> «Хочу, чтобы рубить дерево было приятно: зарубки, шатание, падение по удару.
> Помоги додумать, чтобы не ощущалось как Minecraft».

ИИ уточняет только правила и ощущения, проверяет существующий проект,
помогает сформулировать критерии и ставит согласованную работу в очередь.
Вы не заполняете техническую JSON-карточку.

В чате разработки: `/studio/start` или `/studio/start all`. Результат
проверяется независимым агентом; вам показывают, где его увидеть.
После вашей проверки — `/studio/done`: принять, попросить переделать или
отклонить с причиной. Зелёные проверки и контрольный коммит — ещё не приёмка.

| Команда | Назначение |
|---|---|
| `/studio/setup` | Новый проект или обновление процесса |
| `/studio/idea`, `/studio/roadmap`, `/studio/fault` | Замысел, карта и дефекты |
| `/studio/order`, `/studio/art`, `/studio/music`, `/studio/mockup`, `/studio/need` | Заказы и решения владельца |
| `/studio/start`, `/studio/done` | Разработка и приёмка |
| `/studio/add`, `/studio/check`, `/studio/parallel` | Ассеты, проверки и параллельность |
| `/studio/retro`, `/studio/release`, `/studio/board` | Уроки, выпуск и состояние |

## Модели

`build/models.json` — единственный источник **настроек** моделей ролей.
`studio` использует выбранную в чате модель. Предустановка:

| Работа | Модель |
|---|---|
| executor, scout, assets, reviewer-fast | `opencode-go/glm-5.3-flash` |
| product, architect, designer, reference, reviewer | `opencode-go/glm-5.3` |

Идентификаторы перенесены из вашего прежнего конфига; доступность зависит
от аккаунта и провайдера. Можно задать полный `provider/model` отдельно
каждой роли и выполнить:

```sh
python -X utf8 build/configure.py
```

В контексте проверяется **фактическая модель** против модели профиля:
если OpenCode незаметно наследует другую, плагин сообщает расхождение.
Запасной `<роль>-any` наследует модель чата; его использование должно быть
явно названо в отчёте. Существующая телеметрия токенов/стоимости сохранена.

## Для разработки плагина

```text
.opencode/
  agents/                 короткие роли
  commands/studio/        короткие входы команд
  skills/                 маршрутизаторы процессов и технические навыки
  studio/protocols/        главы исходного CLAUDE_Game
  studio/workflows/        контракт карточки
  studio/runtime/          состояние, контракты, проверки, политика, модели, телеметрия
  studio/templates/       исходные проектные документы и проверяющие скрипты
  plugins/studio.ts        адаптер OpenCode V2
build/                    воспроизводимый импорт и настройка
```

Для регенерации нужны исходники именно закреплённого коммита CLAUDE_Game:

```sh
python -X utf8 build/convert.py --source ../CLAUDE_Game
python -X utf8 build/entrypoints.py
python -X utf8 build/configure.py
python -X utf8 build/check_integrity.py
```

Импорт пересобирает исходные главы, шаблоны и Python-хуки; **не перезаписывает**
ручные контроллеры разработки/приёмки, runtime и короткие роли.
Изменение исходной версии — отдельная сверка. Для проверки разработчику
нужен Node 22.18+ (здесь проверялось на Node 24):

```sh
npm test
python -X utf8 -m unittest discover -s tests -p "*_test.py"
python -X utf8 .opencode/studio/hooks/selftest.py
```

**Статус: кандидат для испытания на реальном проекте.** Локально проверяются
переходы, роли, реальные проверки, восстановление, scope, волны, установка и
исходные Python-проверки. Адаптер проверяется на контрактном стенде V2.
Прогон именно вашего OpenCode с живыми GLM и Godot в этой среде недоступен;
качество игры и разницу с Opus эти тесты не доказывают. Порядок пилота и
известные границы описаны в [docs/MIGRATION.md](docs/MIGRATION.md).
